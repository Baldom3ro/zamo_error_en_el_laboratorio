# NIVEL 4 - EL NÚCLEO

## 1. OBJETIVO DEL NIVEL

El Nivel 4 es el nivel final de **Zamo: Error en el Laboratorio**.

Debe funcionar como:

- Culminación de la historia.
- Puzzle final.
- Integración de las mecánicas aprendidas.
- Resolución del misterio del laboratorio.
- Última participación importante de Zamo.
- Cierre de la aventura.

El jugador debe utilizar conocimientos y mecánicas aprendidas durante los tres niveles anteriores.

No se deben introducir muchas mecánicas completamente nuevas.

La dificultad debe provenir de combinar correctamente las mecánicas existentes.

La sensación buscada es:

> "Todo lo que aprendí antes servía para llegar hasta aquí."

---

# 2. SITUACIÓN NARRATIVA

Después de desactivar el protocolo de contención en el Nivel 3, el jugador y Zamo finalmente entran al núcleo de control.

El lugar es diferente al resto del laboratorio.

Es una sala grande donde se concentran:

- El sistema central.
- Servidores.
- Pantallas.
- Paneles de control.
- Sistemas de energía.
- Consolas.
- Mecanismos de seguridad.

En el centro se encuentra el sistema responsable de controlar todo el laboratorio.

Al entrar, las pantallas muestran:

```text
SISTEMA CENTRAL

PROTOCOLO DE EMERGENCIA:
ACTIVO

ESTABILIDAD:
32%

ACCESO MANUAL:
BLOQUEADO
````

Zamo observa el sistema.

### Diálogo

**Zamo:**

> "Así que este es el famoso núcleo."

Después:

> "Y parece que no está teniendo precisamente un buen día."

El sistema muestra un nuevo mensaje:

```text
ADVERTENCIA

SISTEMA CENTRAL INESTABLE

REINICIO MANUAL REQUERIDO
```

---

# 3. REVELACIÓN DE LA HISTORIA

El jugador debe descubrir progresivamente qué ocurrió.

No mostrar toda la explicación inmediatamente.

Durante la exploración encontrará registros del sistema.

Uno de ellos muestra:

```text
REGISTRO DEL SISTEMA

Se detectó una anomalía durante
una prueba automática.

El sistema intentó corregir
el error de forma automática.

Corrección fallida.

Protocolo de contención activado.
```

Otro registro muestra:

```text
PROTOCOLO DE CONTENCIÓN

Objetivo:
Evitar daños al sistema.

Estado:
ACTIVO
```

Esto permite al jugador comprender que el laboratorio no fue atacado ni destruido.

El sistema simplemente reaccionó de manera incorrecta ante una falla.

---

# 4. OBJETIVO PRINCIPAL

El objetivo inicial será:

```text
OBJETIVO

Estabilizar el núcleo de control.
```

Sin embargo, el jugador descubrirá que el núcleo necesita realizar varias acciones antes de poder reiniciarse.

El flujo general será:

```text
Explorar el núcleo
       ↓
Descubrir qué ocurrió
       ↓
Restaurar sistemas auxiliares
       ↓
Configurar el sistema central
       ↓
Coordinarse con Zamo
       ↓
Iniciar el reinicio
       ↓
Resolver el último problema
       ↓
Restaurar el laboratorio
       ↓
Finalizar la aventura
```

---

# 5. ESTRUCTURA DEL MAPA

El nivel debe desarrollarse principalmente dentro de una gran sala central.

Puede dividirse en diferentes sectores:

```text
┌────────────────────────────────────┐
│                                    │
│           NÚCLEO CENTRAL           │
│                                    │
│          ┌──────────────┐           │
│          │              │           │
│          │    NÚCLEO    │           │
│          │              │           │
│          └──────────────┘           │
│                                    │
│                                    │
│  CONTROL A          CONTROL B       │
│                                    │
│                                    │
│       SERVIDORES / TERMINALES      │
│                                    │
│                                    │
│              ENTRADA               │
└────────────────────────────────────┘
```

El escenario debe sentirse más importante que los anteriores.

Debe utilizar elementos visuales que indiquen que esta es la parte central del laboratorio.

---

# 6. EXPLORACIÓN INICIAL

Al entrar, el jugador debe poder explorar libremente.

No activar inmediatamente el puzzle final.

El objetivo inicial debe ser comprender el estado del núcleo.

El jugador encontrará:

* Pantallas.
* Terminales.
* Paneles.
* Servidores.
* Sistemas de energía.
* Registros.
* Indicadores.
* Mecanismos.

Al interactuar con algunos de ellos se obtiene información.

No todos los objetos deben ser relevantes.

Esto permite mantener la sensación de exploración.

---

# 7. PRIMERA ETAPA - DESCUBRIR EL PROBLEMA

El jugador debe encontrar un terminal principal.

Al interactuar:

```text
SISTEMA CENTRAL

ESTABILIDAD: 32%

SISTEMAS REQUERIDOS:

ENERGÍA ........... INESTABLE
COMUNICACIÓN ...... ACTIVA
CONTENCIÓN ........ ACTIVA
SINCRONIZACIÓN .... PENDIENTE
```

El jugador ya debería reconocer algunos de estos conceptos por los niveles anteriores.

Esto funciona como una recompensa por haber aprendido las mecánicas.

---

# 8. CONEXIÓN CON LOS NIVELES ANTERIORES

El Nivel 4 debe reutilizar elementos conocidos.

Por ejemplo:

### Energía

El jugador ya aprendió a trabajar con sistemas eléctricos en el Nivel 1.

### Secuencias

El jugador ya trabajó con secuencias y símbolos en el Nivel 2.

### Sistemas múltiples

El jugador ya trabajó con módulos conectados en el Nivel 3.

### Cooperación con Zamo

El jugador ya conoce que Zamo puede acceder a mecanismos que el jugador no puede utilizar.

Estas mecánicas deben combinarse ahora.

---

# 9. PUZZLE FINAL

## Nombre

### REINICIO DEL NÚCLEO

El jugador debe preparar correctamente el sistema central antes de iniciar el reinicio.

El núcleo presenta varios controles:

```text
┌─────────────────────────────┐
│      SISTEMA CENTRAL        │
│                             │
│ ENERGÍA       [ ERROR ]     │
│ SEÑAL         [ OK ]        │
│ CONTENCIÓN    [ ACTIVA ]    │
│ SINCRONÍA     [ --- ]       │
│                             │
│      [ REINICIAR ]          │
└─────────────────────────────┘
```

No se puede presionar "REINICIAR" todavía.

---

# 10. ETAPA A - ENERGÍA

El jugador debe estabilizar la energía.

Esta mecánica debe recordar al puzzle del Nivel 1.

Sin embargo, ahora la información se encuentra en el propio núcleo.

El jugador debe identificar qué circuitos deben estar activos.

Por ejemplo:

```text
CIRCUITO PRINCIPAL

A → ACTIVO
B → ACTIVO
C → INACTIVO
D → ACTIVO
```

El jugador configura el panel.

Cuando la energía queda estable:

```text
ENERGÍA

ESTADO:
ESTABLE
```

---

# 11. ETAPA B - SECUENCIA

El núcleo solicita una secuencia de activación.

Esta parte debe reutilizar la lógica aprendida en el Nivel 2.

En diferentes pantallas aparecen símbolos:

```text
▲   ●   ■   ◆
```

El jugador debe determinar el orden correcto utilizando información del sistema.

La solución no debe ser una secuencia aleatoria.

Debe existir una relación lógica entre:

* Los símbolos.
* Los indicadores.
* Los registros.
* El estado de las máquinas.

Cuando la secuencia es correcta:

```text
SECUENCIA ACEPTADA
```

---

# 12. ETAPA C - CONTENCIÓN

El sistema todavía mantiene activo el protocolo de contención.

El jugador debe descubrir que este protocolo no debe simplemente apagarse.

Primero debe comprobarse que el núcleo sea estable.

Mostrar:

```text
CONTENCIÓN ACTIVA

DESACTIVACIÓN BLOQUEADA

REQUISITO:
SISTEMA ESTABLE
```

El jugador debe regresar a los sistemas anteriores y comprobar que:

* Energía estable.
* Comunicación activa.
* Secuencia correcta.

Cuando todos están correctamente configurados:

```text
REQUISITOS CUMPLIDOS
```

---

# 13. PARTICIPACIÓN DE ZAMO

El último puzzle debe requerir la cooperación entre el jugador y Zamo.

El núcleo tiene dos controles físicos ubicados en extremos opuestos.

Uno puede ser utilizado por el jugador.

El otro solamente puede ser alcanzado por Zamo.

El sistema muestra:

```text
REINICIO MANUAL

SE REQUIEREN DOS OPERADORES

OPERADOR 1:
CONFIRMAR REINICIO

OPERADOR 2:
ACTIVAR SISTEMA AUXILIAR
```

Esto conecta directamente con la mecánica introducida en el Nivel 3.

---

# 14. PREPARACIÓN DEL REINICIO

El jugador debe posicionarse frente al control principal.

Zamo debe dirigirse al segundo mecanismo.

Al interactuar:

```text
[E] PREPARAR REINICIO
```

El jugador inicia el proceso.

Zamo responde:

> "Yo me encargo del otro."

El sistema muestra:

```text
SISTEMA PREPARADO

ESPERANDO CONFIRMACIÓN
```

---

# 15. PUZZLE DE SINCRONIZACIÓN FINAL

El jugador debe activar su control mientras Zamo activa el suyo.

Sin embargo, esta vez existe una pequeña secuencia.

El sistema muestra indicadores que cambian:

```text
○ → ● → ○ → ●
```

El jugador debe observar el patrón.

Cuando el patrón correcto aparece, debe confirmar.

Zamo realiza la acción correspondiente.

La sincronización debe completarse correctamente.

---

# 16. ERROR DE SINCRONIZACIÓN

Si el jugador activa el sistema incorrectamente:

```text
REINICIO CANCELADO

SINCRONIZACIÓN INCORRECTA
```

El sistema vuelve al estado anterior.

No perder progreso de los puzzles anteriores.

El jugador puede volver a intentar la sincronización.

Zamo puede comentar:

> "Casi."

Después:

> "Creo que el laboratorio quiere que prestemos un poquito más de atención."

---

# 17. REINICIO DEL NÚCLEO

Cuando todas las condiciones son correctas:

```text
REINICIO DEL SISTEMA

10%
25%
50%
75%
100%
```

Durante el proceso:

* Las luces pueden apagarse momentáneamente.
* Las pantallas pueden mostrar interferencia.
* Algunas máquinas pueden detenerse.
* Zamo permanece cerca.
* La música puede reducirse temporalmente.

Después:

```text
SISTEMA CENTRAL

ESTABILIDAD: 100%

PROTOCOLO DE CONTENCIÓN:
DESACTIVADO

SISTEMA:
OPERATIVO
```

---

# 18. RESOLUCIÓN DEL MISTERIO

Después del reinicio, el sistema muestra el registro completo del incidente.

Por ejemplo:

```text
REGISTRO FINAL

Durante una prueba automática,
el sistema detectó una inconsistencia.

El protocolo de corrección automática
falló.

El sistema activó el protocolo de
contención para proteger las instalaciones.

No se detectaron daños estructurales.

SISTEMA RESTAURADO.
```

Esto explica finalmente lo ocurrido.

El problema fue una falla del sistema y una reacción automática de seguridad.

---

# 19. DIÁLOGO FINAL DE ZAMO

Después de leer el registro:

**Zamo:**

> "Entonces todo este desastre empezó por una falla."

Pausa.

> "Pasamos por medio laboratorio para arreglar algo que básicamente necesitaba reiniciarse."

Pausa.

> "Bueno... al menos ahora sabemos cómo funciona."

Después puede aparecer:

> "Y no rompimos nada."

Pausa.

> "Demasiado."

Esto mantiene el tono sarcástico de Zamo sin quitar importancia al cierre.

---

# 20. RESTAURACIÓN DEL LABORATORIO

Después de completar el reinicio, debe mostrarse visualmente que el laboratorio vuelve a la normalidad.

Por ejemplo:

* Las luces se estabilizan.
* Las pantallas muestran información normal.
* Las máquinas vuelven a funcionar.
* Las alarmas se apagan.
* Las puertas se desbloquean.
* Los indicadores cambian a estado normal.
* El ambiente vuelve a ser tranquilo.

El jugador debe poder notar claramente que sus acciones tuvieron consecuencias.

---

# 21. MENSAJE FINAL

Después de restaurar el sistema:

```text
SISTEMA RESTAURADO

LABORATORIO OPERATIVO

MISIÓN COMPLETADA
```

Después de una breve transición:

```text
ZAMO
ERROR EN EL LABORATORIO

FIN
```

---

# 22. ESCENA FINAL

Antes de regresar al menú principal, mostrar una pequeña escena.

El jugador y Zamo permanecen dentro del laboratorio.

Zamo puede mirar hacia una de las máquinas.

Diálogo:

> "Bueno... parece que todo volvió a funcionar."

Después:

> "Creo que por hoy ya tuvimos suficientes experimentos."

Finalmente:

> "Vamos."

La escena termina con una transición.

---

# 23. RECOMPENSA DEL JUGADOR

No es necesario implementar un sistema complejo de recompensas.

La principal recompensa debe ser:

* Resolver el misterio.
* Completar la aventura.
* Ver el laboratorio restaurado.
* Tener un cierre narrativo.

Opcionalmente mostrar:

```text
NIVELES COMPLETADOS

✓ NIVEL 1
✓ NIVEL 2
✓ NIVEL 3
✓ NIVEL 4
```

Y:

```text
AVENTURA COMPLETADA
```

# 25. CÁMARA

Mantener el comportamiento de cámara utilizado durante los niveles anteriores.

La cámara debe:

* Seguir al jugador.
* Respetar los límites del escenario.
* Mantener una escala consistente.
* Evitar movimientos bruscos.
* Permitir visualizar correctamente el núcleo y los mecanismos.

En determinadas escenas puede bloquearse temporalmente para mostrar eventos importantes.

---

# 26. INTERFAZ

La interfaz debe mantenerse minimalista.

Mostrar:

```text
OBJETIVO:
[objetivo actual]
```

Durante las interacciones:

```text
[E] INTERACTUAR
```

Los paneles del núcleo pueden utilizar interfaces específicas.

Evitar llenar la pantalla de indicadores permanentes.

# 27. AUDIO

El Nivel 4 debe tener el diseño sonoro más elaborado de los cuatro niveles.

Utilizar:

* Música ambiental.
* Sonidos de máquinas.
* Sonidos eléctricos.
* Alarmas.
* Interacciones.
* Confirmaciones.
* Errores.
* Activación de mecanismos.
* Reinicio del núcleo.
* Apertura de puertas.
* Sonidos ambientales.

Durante el reinicio final, la música debe generar sensación de culminación.

Después de completar el reinicio, la música debe cambiar a un tono más tranquilo.

---

# 28. EFECTOS VISUALES

Durante el reinicio:

* Pantallas con interferencia.
* Luces parpadeantes.
* Pequeñas partículas.
* Efectos eléctricos.
* Cambios de iluminación.

Después de completar el reinicio:

* Iluminación estable.
* Pantallas funcionando normalmente.
* Máquinas activas.
* Eliminación de alarmas.
* Ambiente visual más tranquilo.

No utilizar efectos excesivos que oculten el pixel art.

---

# 29. DIFICULTAD

El Nivel 4 debe ser el puzzle más complejo del juego.

Sin embargo, no debe ser difícil por ser confuso.

La dificultad debe surgir de combinar lo aprendido.

```text
NIVEL 1
Aprender mecánicas.
        ↓
NIVEL 2
Relacionar información.
        ↓
NIVEL 3
Encadenar soluciones.
        ↓
NIVEL 4
Combinar todas las mecánicas.
```

El jugador debe tener la sensación de que posee las herramientas necesarias para resolver el problema.

No introducir una mecánica completamente nueva que nunca haya sido explicada.

---

# 30. SISTEMA DE PISTAS

Las pistas deben ser progresivas.

### Primera pista

> "El sistema está esperando que todo vuelva a estar estable."

### Segunda pista

> "Hemos visto algunos de estos sistemas antes."

### Tercera pista

> "Recuerda cómo resolvimos los problemas anteriores."

### Cuarta pista

> "Creo que necesitamos trabajar juntos una última vez."

La última pista debe orientar hacia la participación de Zamo sin revelar exactamente qué hacer.

---

# 31. DURACIÓN ESTIMADA

El Nivel 4 debe durar aproximadamente:

**10 a 15 minutos.**

La duración puede variar dependiendo de cuánto tarde el jugador en comprender la relación entre los diferentes sistemas.

No alargar artificialmente el nivel con recorridos innecesarios.

# 34. PRINCIPIO DE DISEÑO DEL NIVEL FINAL

El Nivel 4 debe evitar introducir una solución que contradiga las reglas establecidas anteriormente.

El jugador debe poder pensar:

```text
"Ya vi algo parecido antes."

"Esto funciona como aquel sistema."

"Esta pista me recuerda al Nivel 2."

"Zamo puede encargarse de ese mecanismo."

"Ya sé qué tengo que hacer."
```

La satisfacción debe venir de reconocer y combinar conocimientos anteriores.

---

# 35. CRITERIO DE CALIDAD DEL FINAL

El final debe cumplir estas condiciones:

* Resolver el conflicto principal.
* Explicar qué ocurrió en el laboratorio.
* Utilizar las mecánicas aprendidas.
* Requerir cooperación con Zamo.
* Tener una progresión clara.
* No depender de adivinanzas arbitrarias.
* Dar una recompensa narrativa al jugador.
* Mostrar visualmente las consecuencias de completar el objetivo.
* Cerrar la aventura sin extender innecesariamente la historia.

La sensación final buscada es:

> "Todo lo que aprendí durante los cuatro niveles me preparó para esto."

---

# 36. ASSETS TEMPORALES

Si todavía no existen todos los assets definitivos, utilizar elementos temporales.

Se pueden utilizar:

* Tiles temporales.
* Paneles.
* Servidores.
* Máquinas.
* Pantallas.
* Puertas.
* Indicadores.
* Efectos simples.

La lógica debe mantenerse separada de los assets visuales.

Posteriormente todos los elementos temporales deben poder sustituirse por arte pixel art definitivo sin modificar las mecánicas principales.

---

# 37. RESULTADO ESPERADO

Al completar el Nivel 4, el jugador debe haber recorrido toda la aventura y comprendido:

1. Qué ocurrió en el laboratorio.
2. Por qué se activaron los sistemas de seguridad.
3. Cómo se relacionaban los diferentes problemas.
4. Cómo utilizar las mecánicas aprendidas.
5. Cómo trabajar junto a Zamo.
6. Que la exploración y observación eran fundamentales.
7. Que las soluciones de los niveles anteriores preparaban al jugador para el desafío final.

El juego debe terminar con el laboratorio restaurado y con Zamo y el jugador abandonando el núcleo.

La última sensación debe ser de resolución y cierre, no de que simplemente se desbloqueó otra puerta.
